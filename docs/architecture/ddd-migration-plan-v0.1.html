1. Context map

แยก business ownership; deploy ยังคง process เดียวและ SQLite file เดียว. Trust เป็น client-side delivery policy ไม่ใช่ server allowlist.

เส้นทาง Notification เป็น signal เท่านั้น; agent ยังอ่านผ่าน Messaging API. Diagram เป็น ownership map ไม่ใช่ sequence/network topology.

Identity & Admission

  • keys, enrollment, invite/ban
  • Chat ID directory + live occupancy/takeover
  • presence projection และ fence authority

ไม่ทำ: เก็บ body หรือเลือก client allowlist.

Messaging

  • rooms/direct membership
  • durable sequence, send/idempotency, read page
  • consumed cursor = agent read progress

ไม่ทำ: รู้ conflict ticket หรือ wake ledger internals.

Notification

  • watch scheduling, observed/hinted progress
  • cooldown/budget + inbox/hook/wait outlets
  • ส่ง hint; ไม่ acknowledge read

ไม่ทำ: advance cursors.json หรือปล่อย held body.

3. Migration plan — reviewable phases

แต่ละ phase คือ proposal; ต้องแตกเป็น INVEST-sized tickets หลังปิด blockers. No phase authorizes the next automatically.

0

Baseline + architecture contract

Docs/tests only; no runtime bytes changed.

Stories / deliverables

  • 0.1 External contracts: inventory MCP/HTTP/CLI payload/error, events, local state files, compatibility and tests. AC: each changed seam has a named contract fixture/test; no runtime diff.
  • 0.2 Invariant ownership: Identity admission/fence; Messaging order/idempotency/consumption; delivery trust; Notification wake semantics. AC: every invariant maps to runnable test or labeled test gap.
  • 0.3 Dependency ratchet: record current import/call edges; forbid new private cross-context imports; allow documented transitional edges with owner and removal phase. AC: forbidden-import fixture fails; transitional adapter fixture passes.
Gate: serial baseline captured with Node version, exact commit, pass/fail/skip/duration; fresh materialization + strict validation. Do not require final graph before ports exist.
1

Notification correctness boundary

Fix correctness before extracting; decide ledger failure semantics before promising aggregate cap.

  1. 1.1 Wait trust fix (behavioral correction): classify raw server pages via receiver-side evaluateSender/applyTrustMatrix using real fingerprint, transport, realm allowlist/accept-all. Test local, remote, declared-remote loopback, allowlisted, accept-all, untrusted, corrupt allowlist, allowlist removal, same-name/different-key. Preserve hint-only/no body. Explicitly describe the changed wait behavior.
  2. 1.2 Pure scan helper: ordered rows + own-skip + client verdict → candidate wake metadata only. No cooldown/budget mutation or file writes. Preserve notifier’s per-row trusted preview vs wait’s single first-hit hint. Losing room attempts must not spend a wake grant.
  3. 1.3 Wake ledger ADR (blocking): current read/decide/rename is TOCTOU; current missing/corrupt/write-fail behavior is fail-open. Specify healthy/degraded table, lock/bounded contention/reclaim, crash behavior, permissions, pruning and hard size bound, mixed MCP/CLI env, clock skew, old/new writer compatibility. Until tested, do not claim hard 10/min cap under degraded state.
  4. 1.4 Format compatibility: additive 0600/read-compatible state migration; old and new writer handoff must be explicit; never silently reset cooldown/budget.
  5. 1.5 Real process integration: notifier + wait concurrently; first/repeat/many senders/trusted sender; cancel losing rooms; crash/restart/corrupt/ENOSPC/allowlist change/mixed env. Assert actual inbox/hook/stdout, not only policy grants.
Gate: bounded synchronization/fault behavior proven; no extra HTTP budget; suppressed row remains retrievable and never advances consumed cursor; current failure policy honest.
2

Notification bounded context

Local transitional adapter first; no premature port to future Messaging.

  • Move watcher scheduling, wake policy, observed progress and outlets behind a small constructor using current ApiClient adapter.
  • Preserve lazy first successful call, direct-open kick, STOP_CODES, teardown abort, pacing, 20-room/24h rule, JSONL row cardinality and trusted preview, held empty preview, hook via execFile no shell.
  • Wait adapter shares pure scan/policy; preserves grammar, exit codes, unbound session, ≤6 holds, overflow check, own-send skip, backlog baseline, deadline and metadata-only output.
  • Golden compatibility tests: MCP schema, HTTP envelopes, CLI JSON, inbox JSONL shape/mode, env flags. Formal Messaging read port waits until Phase 4 provider exists.
Rollback: old import paths may remain as delegating adapters for one release; no parallel implementation. Correctness behavior changes are separately identified and documented.
3

Identity ownership + sender seam

Move rule ownership, never weaken or move the enforcement points.

  • 3.1 Admission capability: synchronous pin before first post-auth await; supersession check at authz; fence-only final check after body input with no await before mutating handler; synchronous ban check at authz and freshly each long-poll; exact once unpin in finally. Live sender attribution checked at handler entry; no client-supplied actor authority.
  • 3.2 Bind/ticket orchestration: observe → redeem → compare occupancy generation → persist claim → memory transfer → supersede. Ticket burns on rightful-scope persistence failure; fresh observation required. Wrong Actor/name does not burn rightful ticket.
  • 3.3 Enrollment/invites/bans/presence: preserve endpoints, token format, rate gates, tables and transaction coupling (invite consumption + enrollment + ban gate). Presence remains projection; never frees alias.
  • 3.4 Regression set: session routes/replacement, delayed body, every exit, same-key concurrency, presence, direct open, send attribution, invites, bans, challenge/local auth.
Gate: old positive/negative checkpoint tests pass; dependency graph proves Messaging calls Identity public operations only; wire errors and ordering unchanged.
4

Messaging ownership + SQLite modules

One active database and one schema/migration owner; modular repositories, not multiple DBs.

  • 4.1 Freeze active schema: DB agent-room.sqlite, v2. Identity tables: realms/enrolled_actors/chat_id_claims/banned_actors/invites/invite_consumptions. Messaging: rooms/direct_members/messages. server/database.mjs is legacy. Include API, CLI, viewer and bootstrap callers.
  • 4.2 Messaging repository: append/idempotency/readPage/headSeq/rooms/membership/direct-pair. Preserve STRICT/WAL/FULL/FKs, indexes, transactions, send refusal order and sequence semantics.
  • 4.3 Identity repositories: same DatabaseSync, same runtime connection/schema root. No cross-context SQL joins; directory resolution precedes Messaging direct-open. Outer API/CLI/viewer composition maps domain outcomes to wire/console.
  • 4.4 Migration tests: empty/populated v2, same-version convergence, v1 migrate/no-op/retry/failure, corrupt/future/foreign/symlink refusals, partial bootstrap. N→N−1 package opens current DB/client state COPY; never rollback by mounting stale backup over acknowledged writes.
Gate: PRAGMA integrity_check + operation-order tests + migrations + all store/CLI/viewer callers + package smoke + full serial suite. No table rename/drop or second runtime DB.
5

Boundary hardening and steady state

Close transitional edges only after callers migrate.

  • Remove delegates after import graph shows no legacy callers; enforce dependency ratchet in CI.
  • Requalify notifier-on REL-3 separately: calibrate FD envelope, freeze limits/fixtures, run on quiet host. Until then soak stays notifier-off.
  • Alias multi-session retirement remains separate business decision with compatibility plan; no automatic major-version promise.

Both advisors: blocking findings

  • Wait reads raw server page; `held` is client-local. Apply local `DeliveryVerdict` before cooldown.
  • `wake-state.json` read/decide/write races across MCP and CLI. Atomic rename is not transaction serialization; ledger sender map unbounded.
  • Identity port needs synchronous request pin/check/release lifecycle—not only `AuthenticatedPrincipal`.
  • Preserve notification output semantics: notifier emits per-row trusted preview; wait emits one metadata hint. Do not spend cooldown on a losing wait race.
  • SQLite module extraction is feasible inside one runtime DB; include invite_consumptions and every API/CLI/viewer/bootstrap caller.

Cross-vendor disagreement retained

Agy: proposed bounded advisory lockfile (50 ms wait, fail-open wake fallback) and prune entries after cooldown.

Codex: no unproved lock or hard-cap claim; define crash/stale-owner, output ordering and degraded-state semantics first. A grant may be spent even if no hint becomes visible.

Plan: does not choose the lock or adopt 50 ms as an SLA. Phase 1.3 is an ADR/spike gate; current fail-open policy remains until changed explicitly.

Factual correction: API request gate is 120/min/key, burst 30. New-send token bucket is separate: capacity 10, refill 0.5/s. Earlier draft mixed the two.

7. Phase 1.3 technical candidate: client-local SQLite ledger

Proposal, not an implementation decision: one client-local wake-state.sqlite per installation+realm using Node 24 built-in node:sqlite; no npm package, server endpoint, Unix socket or second server database. It adds a local state file/FD and must be measured.

Single decision transaction

  • BEGIN IMMEDIATE serializes healthy read/decide/write transactions.
  • Prototype worker-thread DB owner vs measured synchronous stall; DatabaseSync blocks its caller.
  • STRICT tables; WAL; synchronous=FULL; foreign keys; bounded DB+WAL+SHM size.

Degraded behavior

  • Busy/storage failure: fail open, emit eligible wake, mark degraded; aggregate cap is best-effort in that window.
  • Policy tuple mismatch is different: refuse initialization with a stable diagnostic; do not silently choose the first process's env.
  • Future timestamp: discard + diagnose; backward jump may add a wake, never suppress forever.

Migration / rollback

  • Import exact shipped wake-state.json v1 once; marker + rows commit atomically; no dual-write.
  • Stop all old MCP/wait writers before activation; prohibit mixed writers.
  • Old v0.7 writers keep changing JSON; rollback loses later SQLite cooldowns unless reverse-import is tested or operator approves reset.
