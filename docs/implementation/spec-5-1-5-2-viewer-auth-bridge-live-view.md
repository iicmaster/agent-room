## Intent

**Problem:** `docs/epics.md:534-554` — Stories 5.1 and 5.2 (FR-18, HCI-5, DR-3). The v0.2 server has carried the pipeline's viewer slot as a reject-all default since Story 1.3 and four frozen viewer routes as unimplemented rows since the route table landed; the web/ directory still serves the RETIRED v0.1 daemon's shell, which authenticated by a token in the query string — the exact pattern FR-18 forbids. Nothing existed for a human to watch the room with: no credential bridge a browser can hold, no live feed, no presence view.

**Approach:** one viewer surface, two stories, one change set. **5.1** wires the real verifier into the slot Story 1.3 reserved: `GET /viewer/auth` (viewer class) passes the auth stage by design — the bridge is where the credential is PRESENTED, the same discipline as the pre-auth class — and its handler performs the one check it exists for: the Bearer credential is the CURRENT viewer token (the 0600 `viewer-token` file in the shared data dir), compared constant-time. Success mints a cookie whose value is an INDEPENDENT 256-bit random value (never the token), registered by its SHA-256 digest alongside the token digest it was minted under, and delivered `HttpOnly; SameSite=Strict; Path=/viewer` as a browser session cookie. A query-string credential is structurally impossible: every viewer route's frozen request-field set is empty, so `?token=…` dies in the field gate as `unknown_field` before any handler. Every OTHER viewer route authenticates by that cookie through the slot's real verifier (an injected `viewerVerifier` still overrides — the session slot's default-plus-override pattern); session tokens and Bearer viewer tokens authenticate nothing there, and the cookie jar is per server instance. Rotation is the operator's: `agent-room viewer rotate` on the 4.2 CLI host (AR-13 — no operator HTTP route; the receipt shows the new token exactly once, the invite-mint pattern) atomically replaces the file, and because BOTH the mint and every cookie verification re-read the file per request — the ban gate's uncached-read discipline — the old token refuses at its next mint and every outstanding cookie is invalid at its next presentation, cross-process, no restart. **5.2** makes the surface live: the store gains `readBroadcastPage` — readPage's projection and cursor semantics with the broadcast KIND as the only ACL — so DM exclusion is by construction (a direct id answers the same `room_not_found` a fabricated id answers; no fingerprint argument exists to widen it); `GET /viewer/api/rooms/:id/messages` serves the actor read contract's projection over that read; `GET /viewer/` serves the rebuilt shell (whitelisted asset names only) plus a generated `/viewer/boot.json` descriptor (realm id + Broadcast Room id + version — the only discovery a viewer gets, and it names the Broadcast Room only); and `GET /viewer/api/rooms/:id/events` is THE one SSE stream (DR-3): `event: message` frames with `id: <seq>` plus `event: presence` snapshots on a single `text/event-stream` response. The stream is as gated as any route (cookie at the stage, broadcast-kind probe BEFORE the first byte) and extends the server's established bounded re-poll pattern — it wakes at `LONGPOLL_POLL_INTERVAL_MS`, reads short statement-level pages (never a held read transaction), recomputes the live presence snapshot, and writes a frame only when something changed; a committed message renders well inside `VIEWER_FRESHNESS_SECONDS`, keep-alive comments ride `SSE_KEEP_ALIVE_SECONDS`, a dropped stream reconnects via the `retry:` hint and resumes from the `Last-Event-ID` header (strict digits, junk → `invalid_cursor`) with exact replay. Every viewer response — HTML, JSON, refusal, stream — carries the strict CSP (the retired v0.1 daemon's profile: `default-src 'self'`, no inline script, no framing) plus `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`; the shell renders every text through createElement/textContent only. The client never polls: one EventSource carries room AND presence (the app keys its FR-18 states off these wire facts — authenticated/loading/empty from the stream's open and first frames, online/offline-recently from the snapshot groups, unreachable from a refused connection, reconnecting from a dropped stream, token-rotation from a 401 answer).

## Boundaries & Constraints

**Always:** mint the cookie value from fresh `VIEWER_COOKIE_BYTES` random bytes (never the token, never derived from it); hold only digests in the registry (cookie digest → minted-under token digest), keyed per server instance like the rate gates — admission state is never shared across instances; enforce the cookie attributes exactly (`Path=/viewer`, `HttpOnly`, `SameSite=Strict`, session lifetime — no Expires/Max-Age); pass `/viewer/auth` through the auth stage and perform its one Bearer check in the handler (shape-gate on `VIEWER_TOKEN_PATTERN` before the constant-time compare); read the token file per request through the READ-ONLY reader (bounded regular non-symlink file, `O_NOFOLLOW`) — the HTTP surface never creates or rewrites it; refuse every non-broadcast room on the viewer read paths with the canonical `room_not_found` (same answer as a fabricated id — no existence or kind leak); validate the SSE resume cursor strictly (digits only, else `invalid_cursor`) before any stream byte; run the broadcast-kind probe before the stream headers so a Direct Room answers a normal JSON refusal, not half a stream; apply the security headers at dispatch for EVERY viewer-class response; keep all numeric bounds in the constants module (`VIEWER_TOKEN_*`, `VIEWER_COOKIE_*`, `VIEWER_SESSIONS_MAX`, reusing `SSE_*`, `LONGPOLL_POLL_INTERVAL_MS`, `WEB_ASSET_MAX_BYTES`, `VIEWER_FRESHNESS_SECONDS`); keep the frozen route table's field sets untouched (viewer routes take no credential FIELDS); keep the operator surface on the 4.2 host with the JSON-lines grammar (0 ok / 1 refusal / 2 usage).

**Block If:** a viewer credential (token as Bearer or the cookie) authenticates any non-viewer route — halt; the two verifier slots are the whole mechanism. A session token authenticating any viewer route — halt. A credential in any query string, log line, or referrer-leaking surface — halt; the empty field sets, the no-store/no-referrer headers, and the per-request stderr scan are the proof. A cookie whose value is the viewer token (or any derivative of it) — halt; the cookie must be an independent random value so the long-lived file secret never rides a browser jar. Any handler other than the bridge accepting a Bearer on the viewer class — halt. A viewer read that can name a Direct Room, or a refusal that leaks a direct room's existence or kind — halt; `readBroadcastPage` is the only viewer read. A second client-side feed (polling, a second stream, a websocket) — halt; DR-3 is ONE SSE stream. A stream that starts before the room-kind probe — halt. A viewer response without the CSP — halt, including refusals and the SSE stream. An operator rotation that requires a server restart, or any cached token digest in the serving path — halt; the per-request file read is the rotation mechanism. A NEW public error code, wire field, or route row — halt; the frozen vocabularies gain nothing (boot.json's fields, the presence snapshot's fields, and the message projection are all already in `RESPONSE_FIELD_VOCABULARY`).

**Never:** never put a credential in a URL, query string, log line, or tool-visible surface; never let the server write the viewer-token file (creation/rotation are the operator side); never give the viewer an enumeration route, a DM read path, or a write path; never set-cookie on a failed mint; never hold a SQLite read transaction across the SSE wake; never restate a constant; never widen the wildcard asset serving beyond the whitelisted names (`index.html`, `app.js`, `styles.css`) and the generated `boot.json`; never let viewer requests touch presence liveness (the viewer principal carries no session key, so the touch path cannot fire — already pinned by tests/presence.test.mjs); never skip, `.only`, or todo anything.

## Spec Change Log

- 2026-10-06 (this story): spec authored with the implementation (Stories 5.1 + 5.2 as one change set). Design decisions recorded where the epic text is silent, all grounded in the landed code: (1) the bridge route passes the auth stage by design and its handler owns the one Bearer check — the pre-auth class's discipline, applied to the one viewer route where the credential is PRESENTED; (2) the cookie value is an independent 256-bit random value registered by digest beside the token digest it was minted under, so the long-lived file secret never rides a browser jar and rotation can invalidate wholesale by digest comparison against the CURRENT file read; (4) the cookie is path-scoped to /viewer and a session cookie (no Expires/Max-Age): closing the browser drops the credential, and no new lifetime constant is invented; (5) DM exclusion is the store's `readBroadcastPage` (kind as the only ACL, same `room_not_found` as a fabricated id — no existence or kind leak), not a handler filter; (6) DR-3's "no polling" is a CLIENT contract — one EventSource, no second feed — while the stream's server side uses the long-poll read's bounded re-poll pattern (short statement-level reads, never a held transaction), the codebase's established freshness mechanism, giving sub-250 ms delivery against the 5 s bound; (7) `Last-Event-ID` is the resume cursor (strict digits, junk → invalid_cursor before any stream byte), which makes reconnecting a replay guarantee; (8) `/viewer/boot.json` rides the frozen wildcard row and carries only the already-frozen response fields (realm_id, broadcast_room_id, version) — the one discovery a viewer needs, naming the Broadcast Room only; (9) every viewer response (including refusals and the stream) carries the strict CSP + no-referrer + nosniff + DENY, applied at dispatch; (10) rotation is `agent-room viewer rotate` on the 4.2 host with the new token shown exactly once in the receipt (invite-mint pattern) — AR-13, no operator HTTP route.
