## Intent

**Problem:** `docs/epics.md:320-330` (FR-12, realizing UJ-3) requires that a returning session — one whose client died, slept, or lost connectivity — re-authenticates through the local mechanism, re-claims or re-picks its Chat ID, enumerates its rooms via `GET /api/rooms` (discovering DMs opened in its absence), catches up per room to head-at-read-time in bounded pages from the persisted client cursor, and retries a lost connection on a backoff that runs 1 s→60 s with jitter, with a detected network recovery permitting an immediate attempt. The Epic-1 substrate already owns most of this: re-authentication and the dead-holder re-claim are live (`server/api/server.mjs:188-200`, `:262-271`), the read contract returns `next_after_seq`/`head_seq` over strictly-greater cursor pages bounded at 200 (`server/api/server.mjs:467-512`), and client-owned cursors never move backward (`server/mcp-stdio.mjs:301-320`). But three pieces do not exist: **`GET /api/rooms` is declared in the frozen route table yet not implemented** (`server/api/routes.mjs:45` carries no `implemented: true`, so requests 404 behind the unregistered-route fallback), the store has **no membership query** that can answer "the rooms this Actor belongs to" (`server/store/room-log.mjs` exposes `getRoom`/`findBroadcastRoom`/`readPage` but no list), and **no backoff exists anywhere in the client** — the api-client's only recovery is one immediate re-ensure-and-retry (`server/client/api-client.mjs:336-354`), while the declared backoff constants (`RECONNECT_BACKOFF_MIN_SECONDS`/`MAX_SECONDS`, `server/constants.mjs:40-41`) have zero consumers. The route the wire contract promises is a silent 404, and FR-12's enumeration and retry cadence are prose without code.

**Approach:** one focused production slice plus its proof. (1) Implement the enumeration: a new store function `listRoomsForActor(actorFingerprint)` (the Broadcast Room — membership is implicit per AD-14 — plus every Direct Room whose `direct_members` row names the Actor, in the store's deterministic created-then-id order), a `GET /api/rooms` handler projecting each room to exactly `{room_id, kind}`, the route's `implemented: true` mark, the additive spine AD-8 amendment adding `rooms` to the response vocabulary (and the AD-9 mirror amendment for the two new backoff knobs), and the matching `api-contract.test.mjs` pin updates. (2) Bind the route into the client: `api-client.listRooms()` — every implemented actor route has a client method, and the reconnecting session's enumeration is the client's act. (3) Add the reconnect backoff: an exported pure schedule (`reconnectDelayMs` — exponential from `RECONNECT_BACKOFF_MIN_SECONDS`, capped at `RECONNECT_BACKOFF_MAX_SECONDS`, uniformly jittered by a new declared `RECONNECT_BACKOFF_JITTER`) driving a bounded retry loop in the api-client's existing ECONNREFUSED recovery path, where each backoff wait polls a health probe against the recorded port (`probeHealth`, exported from `ensure-server.mjs` for reuse) and a detected agent-room health answer cuts the wait and attempts immediately. The first attempt stays immediate, so the existing restart-on-a-new-port recovery tests keep their meaning. (4) Prove it all in one new real-server test file, `tests/reconnection.test.mjs`, in the `tests/session-routes.test.mjs` harness style: real spawned server children, real keypairs and local tokens, real `createAgentRoomClient` instances with injected reconnect seams, direct read-only SQLite inspection — plus the filled 2.2 entry in the AC evidence file.

## Boundaries & Constraints

**Always:** derive the enumeration from the store's own membership truth — the Broadcast Room is listed for every Actor without consulting `direct_members` (AD-14's implicit membership, and the review-adversarial H-fix at `docs/architecture/architecture-agent-room-2026-09-20/reviews/review-adversarial.md:143-147` pins that the Broadcast Room is "listed by `GET /api/rooms` like any other room, flagged `kind: broadcast|direct`"), and Direct Rooms only through the caller's own `direct_members` rows; order the response deterministically (`created_at` ASC, then `id` ASC — the same ordering `findBroadcastRoom` uses); project the wire response to exactly `{rooms: [{room_id, kind}]}` from the frozen vocabulary — `pair_key` (it embeds both fingerprints), `title`, `created_by_fingerprint`, and `created_at` never leave the store layer; take identity only from the session token (`sessionPrincipalOf`), never from a request field; keep the route's `requestFields: []` so any query key is an `unknown_field` rejection (pipeline field gate, `server/api/pipeline.mjs:354-372`); make the spine amendment strictly additive and dated, backticking only the new field name so the contract test's parser extracts exactly one new vocabulary entry, and mirror the two new numeric knobs into the spine's AD-9 limit list by a dated amendment (the Story 1.4 precedent); declare the two new knobs (`RECONNECT_BACKOFF_JITTER`, `RECONNECT_RECOVERY_PROBE_MS`) once in `server/constants.mjs` and import them by name everywhere — never restate a literal (AD-9, enforced by `tests/constants.test.mjs`' static scan); keep the backoff's trigger exactly the existing transport-unreachable branch (`outcomeUnknown === true && transportCode === 'ECONNREFUSED'`) and keep the FIRST attempt immediate so the existing single-recovery semantics survive; make the wait loop probe recovery at the declared cadence with `probeHealth`'s `{reachable, agentRoom}` outcome, treating only `agentRoom === true` as detected recovery; bound the loop by the schedule itself — the delays escalate 1 s→60 s (seven waits at the declared constants: 1, 2, 4, 8, 16, 32, 60) and after the capped wait's attempt fails the last real error surfaces, so every tool call terminates and the session-level retry cadence emerges from the agent's own repeated tool calls; thread the caller's abort signal through the loop (a cancelled call stays cancelled, matching `sendMessage`'s rule); inject the test seams (`reconnectSleep`, `reconnectRandom`, `reconnectProbe` factory options) as optional parameters defaulting to real behavior; build every test on real spawned server children with real keypairs, real 0600 local-token files, and real `createAgentRoomClient` instances — zero mocks of the server, the store, or the HTTP path (the injected reconnect seams pace time, they do not fake any component); keep all temp directories under `mkdtemp` outside the repository with ordered `t.after` cleanup that reaps every child; fill the seeded 2.2 entry in `docs/implementation/ac-evidence.yaml` with the real test names and a note stating what the evidence does **not** prove.

**Block If:** implementing the enumeration would require renaming an existing vocabulary field, removing a route, or any non-additive spine change — halt; the vocabulary contract is additive-only (NFR-8, AD-8). A Direct Room the Actor does not belong to ever appears in an enumeration result, or a member room is missing — halt with the SQLite `rooms`/`direct_members` rows; that is an ACL defect, not a query bug. The backoff loop cannot honor the declared constants without restating a numeric literal outside `server/constants.mjs` — halt and extend the constants module instead. The first recovery attempt is no longer immediate and an existing recovery test (`tests/mcp-tools.test.mjs:1042-1099`) fails — halt; that is a regression of the Story 1.7 recovery contract, not an amendment. The loop would retry indefinitely inside one tool call, or retry a failure that is not a transport-unreachable ECONNREFUSED — halt; an unbounded in-call retry hangs the tool result, and widening the trigger would fold FR-20's outcome-unknown resolution into the reconnect path. The enumeration response needs a field outside the frozen vocabulary to satisfy this story's AC — halt and surface the gap in the story result instead of amending the vocabulary beyond `rooms`.

**Never:** do not add a sixth MCP tool or otherwise modify `server/mcp-stdio.mjs`'s tool descriptors, argument allowlists, or cursor machinery — FR-21 (`docs/epics.md:67`) fixes the five-tool surface, `tests/mcp-tools.test.mjs:404`, `:763`, `:784`, `:915` pin it at exactly five, and no requirement names a rooms-list tool; the AC's enumeration surface is the HTTP route the spine already froze, reached through the client (recorded as a decision in the Spec Change Log). Do not change the cursor file format, the monotonic merge (`writeCursors`), or the per-realm write chain — the no-backward property is already enforced client-side and this story proves it, not re-implements it. Do not modify `ensure-server.mjs` beyond exporting the existing `probeHealth` (no staleness-rule, lock, or boot-order change), and never let the backoff's recovery probe write, reclaim, or boot anything — detection is read-only; booting stays `ensureServer`'s job on the attempt itself. Do not reorder `ROUTE_TABLE`, touch its shape, or add a route — the contract test parses the live spine and asserts order. Do not restate or re-derive any limit literal in server, client, or test code (the constants scan fails the suite). Do not touch the retired v0.1 files (`server/database.mjs`, `server/roomd.mjs`, `server/daemon-client.mjs` — retro item `epic-1-retro-item-3` is Story 2.3's). Do not implement the v0.1→v0.2 migration, the churn harness, or the kill-drill (Stories 2.3–2.5), and do not assert remote re-auth (Ed25519 re-proof is Story 4.1's per the AC's own parenthetical). ## Design Notes

**Why the enumeration is a store membership query, not a registry read.** The rooms an Actor "belongs to" have two different membership truths by design: the Broadcast Room is open to every Actor implicitly (AD-14 — no membership rows exist for it, and the schema comment at `room-log.mjs:367-368` says so verbatim), while Direct Rooms are exactly the `direct_members` rows. The review-adversarial H-fix rejected the enrollment-row alternative precisely because it would fork the membership model; listing broadcast rooms unconditionally and DMs through the ACL table is the single mechanism both halves of the fix agree on. Privacy falls out for free: a room the Actor does not belong to is not in the query, and a projection that carries only `room_id` and `kind` cannot leak `pair_key`'s embedded fingerprints even for the caller's own rooms.

**Why the handler projects, and why the vocabulary grows by exactly one name.** The store's `plainRoom` rows are rich (id, kind, title, pair_key, creator, created_at) because the store is the durability boundary; the wire is the frozen-vocabulary boundary. The projection is where the two meet, and keeping it literal (`{room_id, kind}`) makes the response's shape auditable at a glance. The contract test parses the live spine's AD-8 sentence and deep-equals both vocabulary arrays in order, so the amendment's discipline is mechanical: one new backticked name in the responses segment, one appended entry in `RESPONSE_FIELD_VOCABULARY`, prose that names no other field in backticks (the Story 1.6/1.7 amendments are the precedent — their prose deliberately unbackticks `chat_id`, `fingerprint`, and friends).

**Why the backoff lives in the api-client and not the adapter.** The api-client is "the one client the MCP adapter speaks through" and already owns the two recovery disciplines (401 re-auth, ECONNREFUSED re-ensure); the reconnect schedule is the third, generalizing the second. Putting it in `mcp-stdio.mjs` would split the client's recovery story across layers and drag the schedule into the tool-result framing. The client factory's option-seam pattern (`waitMs`, `requestTimeoutMs`) extends naturally: `reconnectSleep`, `reconnectRandom`, and `reconnectProbe` are optional, default to real behavior, and exist so the story's tests can prove the full 1 s→60 s escalation in milliseconds without a single fake component — the server children, tokens, and transports in the loop rows are all real; only time is paced.

**Why detection is a health probe, and why it must stay read-only.** In Local Mode "the network" is the recorded server: `ensure-server.mjs:237-258` defines stale as dead pid AND unreachable health, and `probeHealth` is the bounded probe that decides it (a trickle responder cannot hang it; a foreign responder is `reachable` but not `agentRoom`). Exporting it for the client's wait loop reuses the exact predicate the substrate already trusts. The probe only reads — `runtime.json` plus `GET /health` — because recovery *detection* and recovery *causation* must not blur: booting a replacement server is `ensureServer`'s job on the attempt itself, and a probe that could boot would turn a backoff wait into a side-effecting retry. Only `agentRoom === true` counts as recovery; `reachable`-but-foreign stays waiting.

**Why catch-up needs no new code, and how the story still proves it.** The catch-up discipline is emergent from three existing contracts: pages are bounded (`READ_PAGE_MAX` 200 server-side, `READ_PAGE_DEFAULT` 50 client-side), every response carries `next_after_seq` (strictly-greater resume) and `head_seq` (the room's largest allocated seq), and the client-owned cursor merges monotonically so no read — explicit low page included — can regress it. A reader that loops "read from the cursor until `next_after_seq` reaches the `head_seq` observed at that read" is FR-12's catch-up, and traffic arriving mid-loop is just a moving head the same loop absorbs. The story's rows prove each edge with a real 120-message backlog: bounded tiling with no gap or re-delivery, mid-catch-up arrival absorbed, and the low-page re-read leaving the durable cursor untouched — the same no-reset property Story 2.1 proved across a restart, now proven during active catch-up.

**Why the re-claim rows are shaped the way they are.** Reconnection's identity half is already built: the local token file exchange re-issues the session token (`server.mjs:188-200`), the bind re-claims the configured Chat ID, and the dead-holder release frees a stale same-Actor holder. What differs per absence scenario is which registry state the server holds: after a restart both registries are empty (in-memory by design), so the re-claim is immediate; against a live server whose holder row is still inside the 12 h sliding lease, the bind refuses `chat_id_taken` and the AC's "or re-picks" path applies (setup re-run → new name; the old durable claim row stays either way, because claims are never deleted on connect). The rows test the two reachable paths and record the lease boundary honestly rather than inventing a session-TTL knob no requirement asks for.
