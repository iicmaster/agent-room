# Story 1.2 Audit — codex-advisor[luna] (gpt-5.6-luna[max])

## Verdict
FIX-FIRST — the SIGKILL test kills before `appendMessage` acquires its transaction, so the crash-before-commit acceptance criterion is unproven.

## Findings
- [blocker] Crash test never reaches the insert — `tests/store.test.mjs:321-326` acquires a second `BEGIN IMMEDIATE` lock and signals `READY` before `appendMessage` at `:327-335`; the parent kills the child after 750 ms at `:371-379`. The store's append transaction starts at `server/store/room-log.mjs:267-281` and inserts at `:776-801`. While the second connection holds the writer lock, the child cannot enter that transaction or insert. Reopening with no row and observing seq 1 therefore does not prove rollback after an uncommitted insert. Add a deterministic pause after the actual append insert and before commit, signal at that point, then SIGKILL and assert no acknowledgment, no row, and seq 1 on the next committed append.
- [warning] Generated room ID format has no positive test — IDs are generated with `randomBytes(16).toString('base64url')` at `server/store/room-log.mjs:647,688`; `tests/store.test.mjs:820-824` only rejects a malformed input ID. The explicit opaque-base64url contract is implemented but not asserted for either room-creation path. Assert both generated IDs match the base64url form.
- [warning] New numeric policy choices bypass the constants module — `server/store/room-log.mjs:446-447` adds an 8-attempt open retry cap and 25 ms backoff, and `:647,688` chooses 16 random bytes for room IDs. These choices are not specified in the story or named in `constants.mjs`, despite its single-source rule (`server/constants.mjs:1-5`). Put these choices in named constants or remove the uncontracted retry policy and record the ID entropy choice centrally.
