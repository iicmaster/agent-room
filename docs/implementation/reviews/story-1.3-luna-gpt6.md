# Story 1.3 Audit — codex-advisor[luna] (gpt-6-luna[max])

## Verdict
FIX-FIRST — bootstrap persists a fabricated Actor fingerprint, startup can leak a live listener, and API fallback paths do not meet the protocol contract.

## Findings
- [blocker] Bootstrap persists a fabricated Actor fingerprint as the Broadcast Room creator — evidence: server/core/realm.mjs:15-20, 42-45 defines an all-zero SHA-256 value as a synthetic system fingerprint and passes it as actorFingerprint; server/store/room-log.mjs:329, 671-673 stores it in the non-null created_by_fingerprint column; tests/api-host.test.mjs:492-497 locks that value in. This conflicts with docs/implementation/epic-1-context.md:26, which says fingerprints derive from an installation key and there are no placeholder identities. Represent system-created ownership explicitly without persisting an Actor-looking fingerprint, then test that invariant.
- [blocker] A runtime-record write failure leaks the listening server — evidence: server/api/server.mjs:142-159 starts listening before atomicWriteJson; the catch at :184-190 closes only the store. If runtime.json cannot be written, startServer rejects while httpServer remains live and the store is closed. Retain the server through startup cleanup and close it on every failure after listen. The startup test at tests/api-host.test.mjs:526-544 fails before listen and does not cover this path.
- [warning] Unmatched /api paths bypass protocol enforcement, echo, and centralized status — evidence: the spec says any /api/* request without the header gets 400 and valid /api responses echo it (spec:38-40), while server/api/server.mjs:76-79 returns an immediate hard-coded 404 before pipeline dispatch. The test at tests/api-host.test.mjs:473-477 enshrines that behavior for /api/nope. A valid header also is not echoed if handleRequest throws because the catch at server/api/server.mjs:131-138 responds without protocolEchoHeaders. Resolve the spec's any-/api versus unknown-path 404 precedence, then route unmatched API requests consistently and derive fallback status from reject(...).status.
- [warning] Unknown-field rejection is incomplete and route allowlists are mutable — server/api/pipeline.mjs:45, 248-279 parses bodies only for POST/PATCH, so body fields on GET/DELETE are silently ignored; server/api/routes.mjs:24-49 freezes route objects but not their nested requestFields arrays, which callers can mutate to accept unknown fields. tests/api-host.test.mjs:301-379 covers GET query fields and POST bodies, not these cases; tests/api-contract.test.mjs:101-105 does not assert deep immutability. Reject non-empty bodies on unsupported methods and freeze each allowlist.
- [warning] The contract test pins a duplicate snapshot rather than the live spine, and response vocabulary gaps are frozen — tests/api-contract.test.mjs:38-44 embeds AD-8 text; :76-89 compares implementation data only to that copy, so later spine drift is invisible. server/api/server.mjs:38-40 emits result.version, absent from server/api/routes.mjs:72-83's response vocabulary. The spine also requires GET /api/status to publish realm_id (ARCHITECTURE-SPINE.md:149), but AD-8's response vocabulary omits it (ARCHITECTURE-SPINE.md:113); Story 1.3's test currently freezes that omission ahead of the status handler. Compare the contract to the authoritative spine and reconcile version/realm_id response fields before adding downstream handlers.
