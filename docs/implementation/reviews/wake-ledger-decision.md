## Party decision

**Choose exactly one prototype: candidate C — one client-local SQLite sidecar in DELETE/FULL journal mode, owned by one bounded Worker per process, with `BEGIN IMMEDIATE` around read/prune/check/grant.** No JSON fallback writer, no lockfile protocol, no parallel A/C switch, no new external dependency, no server-side trust state, no Unix socket. The Worker—not the MCP main event loop—owns its single `DatabaseSync` connection. `SQLITE_BUSY` waiting remains bounded; queue/request deadline and worker crash policy must be implemented as specified below before caller wiring.

Rationale: both existing callers are separate processes; atomic rename protects replacement, not decision serialization. SQLite's writer transaction serializes the decision and provides crash-journal recovery using an existing built-in. DELETE/FULL was chosen for the prototype to avoid a separate WAL growth/checkpoint surface; if commit/reader interaction cannot meet the measured timeout, reject C instead of adding a second hidden journaling design.

### Failure policy (product trade-off)

- **First-contact signal outranks bookkeeping only after the process has a valid, matching policy handshake.** During a healthy policy epoch, SQLite transaction decides cooldown/budget.
- A **known mismatch** in realm, receiver fingerprint, format, stored policy tuple or unsupported schema refuses held-row wake decisions with a stable diagnostic, no mutation. This prevents two binaries/processes from making decisions under incompatible cooldown/budget settings.
- A **cold ledger that cannot be read/initialized/imported** cannot prove whether there is a mismatch. It fails open for the otherwise eligible first-contact hint, marks the result degraded and emits a rate-limited diagnostic. No cooldown/budget grant is recorded. Hence aggregate 10/min is guaranteed only in a healthy serialized epoch; never claim a hard cap while degraded.
- Storage/lock failure after a process validated the epoch also emits one degraded eligible hint; no durable charge. Grant-before-output may consume a healthy cooldown without visible output if the process dies after COMMIT. This at-most-once signal gap is accepted; no exactly-once promise or compensating outbox is added.
- Changing policy requires all notifier/wait processes for that PLUGIN_DATA stopped, then an explicit policy-update/rehydration operation. Do not silently make “first process to open” the administrator. Existing env overrides remain inputs to the initial tuple; a stored tuple mismatch refuses until the upgrade/config action reconciles it.

## Concrete implementation contract (prototype AC)

1. **Schema / connection:** fixed tables `wake_policy_meta` (singleton format/realm/receiver/policy tuple/epoch/import marker), `sender_cooldowns` (raw 32-byte fingerprint, last grant), `held_wakes` (bounded timestamp slots). On every connection set and read back `STRICT`, `journal_mode=DELETE`, `synchronous=FULL`, `foreign_keys=ON`, `locking_mode=NORMAL`, bounded `busy_timeout`; no `ATTACH`, triggers, virtual tables or extensions. DB and any journal file 0600; realm directory 0700; use `O_NOFOLLOW`/fstat or refuse if safe managed-path assumptions do not hold. A current Node API limitation is explicit: `DatabaseSync` opens by pathname, not a prevalidated FD; plan’s threat boundary is owner-controlled PLUGIN_DATA (not protection from a malicious same-UID process racing path components). If that boundary is unacceptable, reject C under current constraints.
2. **Worker / bounds:** one persistent Worker per process and at most one Worker for a ledger path; no one-thread-per-request, no unbounded map/queue. Queue cap 64 including in-flight, queued work deadline 250 ms, decision deadline 500 ms from admission, SQLite busy timeout 50 ms, at most four BEGIN attempts with ≤20 ms backoff inside deadline. Bounded response/request shape; no body/secret. Worker late result after caller timeout cannot produce a second output. Worker crash: fence generation, stop dispatch, wait termination; at most one restart per 60 s after exit confirmed, re-handshake. Do not claim a hard process shutdown deadline for kernel-stuck fsync; disclose limit.
3. **Healthy transaction:** `BEGIN IMMEDIATE`; prune expired sender/window records; check policy tuple, sender cooldown, aggregate budget; commit denial-prune or one grant; rollback on error. No await or HTTP/output inside transaction. Time model: persisted epoch, `T=max(now,last_grant_ms)`; future timestamps are treated expired and diagnosed, backwards wall-clock jumps may cause an extra wake but cannot suppress indefinitely. Tests inject ±24 h.
4. **Policy/state bounds:** cooldown=300000 ms, budget=10, window=60000 ms defaults, validated against a fixed supported range before init. Healthy budget creates at most 10 held grants/window, so sender rows are also bounded by active cooldown cohorts (default ≤50; assert); hard maximum sender rows 4096. Main DB ≤4 MiB and DELETE journal ≤8 MiB for the fixed transaction workload; **must measure** 100 cycles at max supported settings and crash recovery. If cap/SQLITE_FULL persists after one bounded prune/recovery attempt, emit degraded eligible hint without grant; never erase active cooldowns. These numeric ceilings are prototype limits, not user-configurable inputs; a request outside them refuses with actionable diagnostics.
5. **Migration:** stop all old writers (v0.7 JSON writer is not fenced by SQLite). New initializer imports exactly supported `wake-state.json` format v1 once, validates path/shape/version/fingerprint/timestamps/policy bounds, commits imported rows and marker in one DB transaction; JSON remains unchanged and is never dual-written. Missing JSON = empty initial state; malformed/unknown/future/oversized input follows cold degraded/fail-open table, no silent marker. Rollback to v0.7 will ignore later SQLite state; either test reverse handoff or document cooldown reset and get operator approval before rollout. Do not overwrite stale acknowledged message data.
6. **Output / wait race:** probe pages are pure. Wait settles candidate cohort, orders by `(seq, room_id, documented order)`, chooses a candidate, then asks the Worker for a grant. Losing rooms never reserve. Abort/drain loser HTTP and await before releasing wait.lock; error precedence/fatality pinned. Notifier output remains per-row with trusted bounded preview; held preview empty. Wait output remains one metadata hint. Suppressed rows are never marked consumed; wait has per-process suppression to avoid hot loop, but a new invocation re-evaluates. Cursor/held/allowlist server data never mutated by wake ledger.

## Reject criteria (no changing acceptance to turn red green)

Reject candidate C and return to a new ADR if: healthy 40-process race grants ≠10; same-sender race grants ≠1; DB/WAL-or-journal exceeds the declared byte bound; client main thread blocks beyond specified budget; worker queue or state rows are unbounded; path/symlink assumptions do not match the operator's threat boundary; held body leaks; any wake advances consumed cursor; or mixed-version/policy rollback cannot be made explicit. Test degraded runs separately; do not re-label expected race oversubscription as degraded to mask a healthy-path failure.

## Minimum tests before any release claim

- 40 independent Node processes, same realm+policy+window: exactly 10 visible grants, 30 denials, 0 degraded in healthy run; 100 repeats with p50/p95/max.
- 20-process same fingerprint race: one grant; 19 cooldown denials; after logical +300 s, one additional grant.
- Same-process MCP + wait, 6+ rooms, trusted candidate after held candidates, all completion orders: no losing grant; no more than one wait hint; losers canceled/drained; no body leakage.
- Startup races, invalid schema/identity/tuple, malformed/missing/imported JSON, transaction kill before COMMIT and after COMMIT, worker crash, stuck response, queue overflow, busy, ENOSPC, read-only path, symlink/hardlink/unsafe realm, DB+journal cap, clock forward/backward.
- Policy mismatch is refusal; busy/storage failure emits degraded first-contact as specified; cooldown is best-effort only while degraded; diagnostics are bounded/redacted.
- Test current JSON-v1→SQLite import, old/new mixed-writer refusal/handoff, and rollback/re-upgrade on copies of real client state. Verify permission modes and DB integrity on actual supported Node/SQLite runtime.

## Preserved disagreement

🪵 **Splinter's hold:** same-UID path replacement cannot be proven impossible with pathname-only `DatabaseSync` and current standard-library surface. A hard hostile-same-UID race guarantee would reject candidate C unless that threat boundary changes or a separately approved native mechanism is added. Splinter also prefers A (WAL) if a hard physical bound can be proven; no such bound is established here.

🃏 **Wildcard's counterweight:** cold fail-open maintains first-contact notification but weakens mismatch protection when the ledger cannot be read; if the operator later requires mismatch-refusal under cold corruption, that is a separate business/security decision, not implied by this technical choice.
