## Verdict
FIX-FIRST — the core schema behavior passes the tests, but the error vocabulary is not centralized and the crash test does not exercise the real append acknowledgment path.

## Findings
- [blocker] Error codes bypass the constants contract — `server/store/room-log.mjs:80`, `server/store/room-log.mjs:198`, `server/store/room-log.mjs:220`, `server/store/room-log.mjs:305`, and `server/store/room-log.mjs:320` throw `invalid_argument`, `wal_unavailable`, `database_configuration_failed`, `database_schema_unsupported`, and `database_schema_invalid`; these codes are absent from `server/constants.mjs:90` and `server/constants.mjs:121`. This violates the Story 1.2 boundary requiring every error name to come from `PUBLIC_ERRORS`/the constants source (`docs/implementation/spec-1-2-store-schema-v2-rooms-the-durable-log.md:27`) and leaves no centralized status mapping for them, contrary to AD-8 (`docs/architecture/architecture-agent-room-2026-09-20/ARCHITECTURE-SPINE.md:106` and `:113`). Register and import the codes through the single constants error/status source, or define and test an explicitly internal-only error registry while keeping every wire-visible code in `PUBLIC_ERRORS`.
- [blocker] The SIGKILL test does not prove crash-before-commit for `appendMessage` — `tests/store.test.mjs:193` says the child closes the store at `tests/store.test.mjs:208`, opens a new raw `DatabaseSync` at `tests/store.test.mjs:209`, and hand-inserts hard-coded `seq=1` at `tests/store.test.mjs:210`–`:213`. It never calls `appendMessage` or observes a send acknowledgment. The test can pass even if the real append path later acknowledges outside its transaction. Add an instrumentable child-process path that invokes the real append and is killed before its real commit/return, then assert no result was acknowledged and recovery reuses seq 1.
- [warning] The single-writer concurrency boundary is source-reviewed but not exercised — `tests/store.test.mjs:112`–`:138` appends sequentially; no two writer connections or child processes append different messages to one room. The implementation uses `BEGIN IMMEDIATE` at `server/store/room-log.mjs:225` and allocates with `MAX(seq)+1` at `server/store/room-log.mjs:554`, but a regression moving allocation outside the transaction would still pass the Story 1.2 tests. Add real concurrent writers and assert committed sequences are exactly `1..n` per room with no gaps or duplicates.
