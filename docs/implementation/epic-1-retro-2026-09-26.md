## Findings

### Aggregate view — architecture delta

**F1 · The v0.1 daemon is still in the shipped package, and the epic's own code stopped using it.**
`server/roomd.mjs`, `server/database.mjs` and `server/daemon-client.mjs` were never modified across
the whole range (git evidence: absent from the churn list) while `mcp-stdio.mjs` was rewritten onto
HTTP in Story 1.7. `scripts/package-release.mjs` copies `server/` wholesale, so the retired daemon
ships in every release artifact. Source: `git_evidence.py` output (no entries for those three
files), `server/mcp-stdio.mjs:56-69` (the new HTTP path), `scripts/package-release.mjs:45`
(`sharedEntries`). *Disposition: defer — the spec's own boundaries deferred their fate to Epic 2
and 5; carrying them has a real cost (two SQL schemas, two identity models in one tree) that the
next epic should decide rather than inherit silently.*

**F2 · `server/api/server.mjs` grew into the epic's largest production module.**
+1,109 / −65 across the range — the biggest production file, and the one every later story wires
into (routes, session handlers, presence, direct-open, messages, registry, prune timers). *Source:
git evidence churn list.* *Disposition: accept for now, flag for Epic 4 — route registration is
already table-driven and `registerHandler` validates against the frozen table, so the growth is
additive rather than tangled, but it is the file most likely to become a god class.*

### Aggregate view — duplication map

**F3 · The live registry accepted any non-empty actor fingerprint** (corrected 2026-09-26).
*As written in the first pass this finding was stale*: production code already had ONE definition
(`server/constants.mjs` `FINGERPRINT_PATTERN`, with every site importing it), and the three other
declarations luna cited were later patches, a derivation, and a test's own independent pin. The
sweep that actually checked the code found the real defect one layer over:
`server/core/session-registry.mjs` `requireActorFingerprint` accepted any non-empty string, so a
malformed fingerprint reached the durable claims table and surfaced as a store CHECK failure instead
of a clean coded rejection. *Fixed in `cdb79ad`* (validation via the shared constant, message
composed from the shared constants so `server/core/` still embeds no fingerprint literal, plus a
regression test); the doubled anchor in the MCP adapter's derived JSON-Schema pattern went with it.
*Lesson: a finding recorded from a review snapshot ages — the epic changed underneath it.*

### Lens — diff-scope review (bmad-review folded in via the per-story audits)

**F4 · Three of nine stories shipped with their central claim unproven, and review caught all three.**
Story 1.8's held-read wake-up assertion had bounds wider than the deadline, so a server that never
woke on arrival passed; Story 1.4 bound every local session to the shared token, making all
installations one Actor, which would have silently poisoned Story 1.5's durable claims; Story 1.9's
gate passed with `TMPDIR` inside the repository and with a runtime file missing from *both*
packages. *Sources: `docs/implementation/reviews/story-1.8-luna-gpt6.md`, `story-1.4-luna-gpt6.md`,
`story-1.9-luna-gpt6.md`; fixes at `6f0fcb1`, `ec5a10e`, `ddca669`.* *Disposition: fixed — but see
F7: nothing in the loop was designed to catch this class.*

**F5 · The auditor integration failed open once, and the auditor found it itself.**
The build's own report of a missing or unparseable auditor outbox read as `SHIP`. *Source:
`story-1-8-luna-gpt6.md` finding 1.* *Disposition: fixed — the reader is now fail-closed on file
type, mtime, terminal marker and verdict.*

### Lens — behavior check (the epic changed runtime behavior, so the flows were exercised)

**F6 · Both blocking gates were re-run by hand, not read off a green suite.**
Story 1.8's zero-mock first-conversation checkpoint: two real `mcp-stdio` children against one real
spawned server, stable across three consecutive runs. Story 1.9's `claude plugin validate --strict`:
run by hand from a fresh package (`✔ Validation passed`, exit 0) and re-run inside `node --test`
with a negative test that proves the gate bites. *Sources: `docs/implementation/epic-1-completion-audit.md`,
`tests/integration/first-conversation.test.mjs`, `tests/package.test.mjs`.* *Disposition: checked and
clean.*

### Process (reconstructed from triage logs and commits — no session logs)

**F7 · The build loop had no mechanism to catch an AC a later story silently un-fulfilled.**
Story 1.7c added the `agent-room setup` CLI without the runtime gate, breaking Story 1.1's
"any entrypoint exits non-zero" AC. The suite stayed green for the rest of the epic: nothing in
the loop re-reads a *previous* story's AC against the code. It was found only by a post-completion
sweep that checked ACs against code rather than against specs. *Sources: `server/cli/agent-room.mjs`
before `bd91f98` (probed on Node 23.5.0, loaded and printed usage); fix and regression guard at
`bd91f98` and the `ENTRYPOINTS` list in `tests/runtime.test.mjs:21`.* *Disposition: process lesson —
this is the single highest-value item in this retro.*

**F8 · The unattended workflow failed more often than the hands-on loop, and every failure was mine.**
Six runs on Story 1.9: three from script bugs I wrote (a `matchAll` without `/g`, args not carried
across an amendment, believing a workflow subagent has a shell), one from the correct scope guard
catching me editing the repo mid-run, and one from a baseline anchored at plan time instead of run
start. *Sources: the run ids and the four `AmendWorkflow` iterations, each fix committed with a
message naming the cause.* *Disposition: process lesson — the hands-on loop closed the epic; the
workflow is unproven in anger and should not carry a gate story until it has.*

**F9 · Review depth was not uniform across stories, and the depth is where the value was.**
Stories 1.2, 1.4, 1.7 and 1.9 each had two or more review passes and a luna verdict that
overturned the first pass. Stories 1.5 and 1.6 got one pass that found the real defect immediately
(1.6's read-sweep freeing other sessions' names). The variance tracked story size, not care. *Source:
the per-story triage logs.* *Disposition: process lesson — depth is a function of blast radius, and
the loop should scale it rather than fix it.*

## What the four fixes actually found

Closing the action items was not bookkeeping. The sweep for item 1 corrected a finding this
retrospective had recorded wrongly (F3: the four-way fingerprint duplication was a stale snapshot —
the real defect was the live registry accepting any non-empty fingerprint, fixed in `cdb79ad`), and
proving item 6's guard found that the guard itself did not work: story keys are hyphenated
(`1-8`) while epics.md headings are dotted (`1.8`), so the first version never matched and let a
blocking-gate story straight through. Both were caught by running the mechanism rather than by
reading it — the same discipline F7 was created to impose.

## Acceptance verdict

**accepted-with-open-items**

Criteria are **declared** — `docs/epics.md` states them per story, and Epic 1's two blocking gates
are named there as gates on later work.

The basis for the call: all nine stories' ACs are satisfied with executable evidence (the spec
ledger and FR/AR/NFR/HCI trace in `docs/implementation/epic-1-completion-audit.md`), both blocking
gates pass when run by hand, and the suite is green at 306 with zero skipped. Every defect the
reviews found is fixed and the fixes are re-verified.

What holds it to *accepted-with-open-items* rather than *accepted*:

1. **The retired v0.1 daemon still ships** (F1) — a real cost carried into every release artifact,
   and a decision this epic deferred rather than made.
2. **The fingerprint definition is still triplicated** (F3) — a drift risk in the project's single
   most load-bearing value, fixable in one pass.
3. **An AC went unfulfilled for the rest of the epic with a green suite** (F7) — the loop that let
   that happen is not fixed; item 1 addresses it prospectively.
4. **The whole-epic diff-scope review did not run** (action 4) — the one analysis this retro could
   not substitute, because the per-story audits each saw only one story's world.
