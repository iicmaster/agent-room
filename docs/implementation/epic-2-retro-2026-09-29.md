## Findings

### Aggregate view — architecture delta

**F1 · The v0.1 daemon now has a migration owner, but still ships.**
`server/store/migrate-v1.mjs` (+643) implements the absorb-or-stop + one-transaction migration, and
`server/database.mjs` remains byte-untouched as the read-only v1 reference — the planned posture.
But the v0.1 daemon (`server/roomd.mjs`) still ships in every package with nothing calling it.
*Source: git evidence (`server/database.mjs` absent from churn), `scripts/package-release.mjs:45`,
Epic 1 retro F1 (same finding, unresolved).* *Disposition: still deferred — but now Epic 3+ owns a
concrete debt list: after the migration exists, the v0.1 daemon's only remaining value is the
legacy viewer route, and Epic 5 (viewer) should decide its fate rather than Epic 2 having carried
it another cycle.*

**F2 · `server/client/api-client.mjs` absorbed the epic's hardest production logic and its review
surface.**
+265 / −47, now containing the reconnect loop, the foreign-responder refusal, attach-epoch
coalescing, and the single-flight authentication. The drill found a real production bug here
(multi-call recovery double-bind → `chat_id_taken` wedge ~15 s per restart) that every
per-mechanism test missed. *Sources: `ffe5104` (fix commit), the drill's failure record.*
*Disposition: fixed and mutation-covered (14 mutations, zero survivors) — but the module is now
the second-largest production surface after `server/api/server.mjs`; watch it at Epic 4.*

### Process — the workflow was parked, and the hand-loop that replaced it worked

**F3 · The story-build workflow closed zero stories in Epic 2.**
Six failed runs on Story 2.2 (provider errors ×3, orchestrator mid-run commits ×2, and the
baseline guard's own semantics ×1) before the orchestrator parked it and hand-finished 2.2–2.5
with the same review discipline. Every failure mode produced a durable fix: the luna parser now
accepts both observed formats, the baseline guard distinguishes the reviewed surface from pipeline
tooling, the escalation addendum makes mid-run authorizations auditable, and the retry posture is
written into the script. *Sources: `.zcode/workflow-runs/dwfrun-{6f281880,dd4dacae,675f8ca6,34df201a,7a668b26,9941dd61,1b836b34}*`,
commits `207fee1`/`daf7f4d`/`4ff0041`/`5bb082d`/`94d6f76`/`3ca56b6`.* *Disposition: accept — but
the workflow's unattended-proof requirement (Epic 1 retro item 6) remains unmet and carries
forward.*

**F4 · The mid-run commit deadlock was real and structural, not carelessness.**
The original guard required HEAD to be frozen for the whole run, but repairing the script mid-run
requires committing the repair. The fixed guard (commit `4ff0041` + `5d7dea3`) now distinguishes
the reviewed surface (`server/`, `tests/`, contract docs) from pipeline tooling and the story's own
allowlisted surface. *Source: the failing error text preserved in two run records ("HEAD moved from
baseline … with changes outside the pipeline's own tooling" → the relaxed form).* *Disposition:
fixed.*

**F5 · The escalation path was exercised for real and became machinery.**
Story 2.2's implementer escalated when the mandated `GET /api/rooms` broke three pre-existing test
pins; the operator authorized purpose-preserving updates; the authorization is now recorded in
`.escalation-addendum-2-2.json` and the scope guard reads the record instead of the operator's
memory. *Source: escalation `dwfq-34df201a-1`, `5bb082d`.* *Disposition: accept — the mechanism
worked and is auditable.*

## Behavior verification

Exercised end to end (this epic's whole point):

- **REL-2 drill, final run (seed 20260928):** two real MCP children sent continuously across 3
  randomized SIGKILL/restore cycles (kill delays 4,383/2,936/3,858 ms; one strike froze the port
  250 ms) — **53,751 acknowledged == 53,751 readable**, per-room contiguity 1..N, zero duplicate
  ids/seqs, cursors exactly at head, byte-exact UTF-8 payloads, external recorder survived every
  kill. Earlier runs proved the same at 64k messages. *Source:
  `tests/drills/rel2-kill-drill.test.mjs` summary line, reproduced 3× + seed-777.*
- **Migration under chaos:** a real SIGKILL mid-migration on a 180k-row v1 database rolled back
  cleanly and the next boot completed to reference maps; a three-run no-op oracle held. *Source:
  `tests/migration.test.mjs`.*
- **The migration absorbed a live daemon** (fake v0.1 daemon holding runtime.json + the db was
  signalled and stopped before migration) — the absorb-or-stop half of the contract. *Source:
  `tests/migration.test.mjs` absorb rows.*
- **Endurance:** 100-cycle churn kept server FDs within ±5 of baseline (worst drift 0) and the
  memory slope measured −0.17..+0.27 %/s against the 2% rule after warmup. *Source:
  `tests/churn.test.mjs`.*
