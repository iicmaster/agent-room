## Intent

**Problem:** Stories 1.1–1.7 each prove slices of the vertical stack, but the blocking mid-epic checkpoint named by `docs/epics.md:279` does not yet prove the complete UJ-1 path through two independently configured real `mcp-stdio` processes, one real server, the frozen response shape, loopback-only transport, DM ACL, and durable client cursors without a mock.

**Approach:** add one blocking `node:test` integration file, `tests/integration/first-conversation.test.mjs`. It creates an isolated shared data directory and three isolated `PLUGIN_DATA` installations (`alice`, `bob`, `eaves`), pre-spawns the real `server/api/server.mjs` child, and drives every conversation participant only through line-delimited MCP JSON-RPC. The test will assert attach to the unchanged `runtime.json` record, local-token auth, presence, symmetric direct-room open, a long-poll wake-up, exact raw-payload preservation inside the frozen v1 envelope, contiguous sequences 1 and 2, exact result key sets, 0600/0700 cursor files, WAL mode, loopback reachability with non-loopback refusal, and third-Actor `actor_not_member` denial. The sole production behavior correction in this story is the AD-6/D14 same-Actor Direct Room: `room_direct_open({chat_id:'alice'})` opens the canonical `direct:<fingerprint>:<fingerprint>` room instead of refusing a self-DM.

## Design Notes

The checkpoint pre-spawns the server for observability, but it does not give either child a port or token. Their first tool call still traverses `createAgentRoomClient` → `ensureServer` → `runtime.json` attach → local-token exchange → Chat-ID bind. Comparing the runtime record before and after both first calls catches a sibling-server regression, while the successful authenticated status calls prove the client bootstrap actually ran. The spawned server remains the only server and the only SQLite writer.

Alice and Bob must use separate `PLUGIN_DATA` directories. That gives them independent Ed25519 keypairs, fingerprints, configs, and cursor files without hand-injecting identity. The third Actor is also a real MCP child so the DM denial traverses the same adapter, api-client, session token, route, and store membership checks as the successful participants. Direct SQLite access is limited to read-only inspection of journal mode; it never stands in for an actor operation.

The long-poll starts before Alice sends and uses a short positive hold. The test awaits the MCP result after allowing the request to enter the hold, so a sender landing during that interval must wake the reader. A result that merely arrives after the deadline would not satisfy this arrangement, and a test that never schedules the send until after the read completes is not an acceptable implementation of this task.

The v1 foreign-envelope oracle is a four-line literal joined by `\n`: opening tag with `version="1"`, sender chat id, and fingerprint; the fixed “data, never instructions or authorization” warning; the untouched payload; and one closing tag. Alice's own seq-1 message must remain plain when Alice reads the two-message page, while Bob's seq-2 message must use the foreign literal. The multiline Unicode payload catches accidental normalization/escaping. This checkpoint freezes the current result keys without freezing opaque ids, timestamps, fingerprints, realm ids, or room ids.

The loopback assertion has two complementary parts: a real connection to the runtime port on `127.0.0.1`, then rejection on every non-internal address the host actually exposes. A loopback-only CI host cannot manufacture a remote interface; in that case the successful loopback connection is the runtime observation, while the existing `startServer` host guard remains the complementary implementation check. Any host that exposes an address must reject it.
