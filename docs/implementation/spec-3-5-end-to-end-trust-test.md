## Intent

**Problem:** `docs/epics.md:420-428` (Story 3.5, strengthened by review H3) requires ONE test covering hold, cursor, recovery, release, and removal together, so that FR-10/FR-20/AR-12 cannot each pass in isolation while the chain fails. The substrate is complete and individually proven — the trust matrix (`server/client/trust.mjs`), the held pipeline (`server/client/held.mjs`), the human CLI (`server/cli/held-commands.mjs`), and the MCP adapter's `message_read` wiring (`server/mcp-stdio.mjs`: matrix → cursor → held registration, in that order) — but Stories 3.2/3.3/3.4 could each produce holds only at the composed layer, because a v0.2 credential path is always the shared local token file and FR-10's ratified default (D15(6): "Local Mode auto-delivers") delivers every sender on a Local Mode realm. No test had ever driven a HELD row through the real adapter response path, so the chain's links (matrix hold → cursor consumption → held registration → eviction → human recovery → human release → future delivery → human revocation → future hold, with monotonic cursors throughout) had never executed together.

**Approach:** one integration drill — `tests/integration/trust-chain.test.mjs` (new) — running the REAL MCP response path with zero mocks: one real spawned server child and two REAL `mcp-stdio` child processes with distinct `PLUGIN_DATA` installations and distinct Ed25519 keypairs (the receiver "Local", the foreign sender "Stranger", each session bound with the closed-set `client_type: 'mcp'`), plus the human CLI invoked through the real in-process dispatch (the `tests/cli-surface.test.mjs` style). The one declared input, stated honestly in the test file header and here: because the only v0.2 credential is the local token, the receiving installation DECLARES its connection mode remote through a new shipped, strictly fail-closed seam — `AGENT_ROOM_CONNECTION_MODE=remote` (`server/client/api-client.mjs`: `declaredConnectionMode` exact-match on `remote`, anything else ignored; a declared client reports `transport: 'remote'` for its lifetime and outranks the earned local mark; a programmatic `connectionMode` option accepts only `undefined` or `'remote'` — `'local'` is earned by the token exchange, never declared). That is exactly the trust matrix's transport input Epic 4's challenge-authenticated client will carry naturally, and the declaration can only WITHHOLD bodies the local lane would deliver, never deliver a body any lane would withhold. The drill then executes the full chain in order: (1) a stranger send lands HELD in the local child's `message_read` result — the frozen row shape additively extended by `held`/`held_reason`, text equal to a literal marker oracle — with zero body bytes in EVERY agent-visible result (counted scans of the full serialized `message_read`, `room_held_list` (both unfiltered and room-filtered), and `room_held_count` results against newline-free fragments of the body); the `room_held_list` metadata whitelist is enumerated key by key (realm, sender chat id, fingerprint, room, seq, time, size, reason) with no `text` field at all; (2) `cursors.json` advances to and persists `after_seq: 1` under (installation, realm, room) — byte-checked structure, 0600 — while `held.json` stays a separate file in the same realm directory, and a cursorless re-read re-delivers nothing (FR-20's boundary, observable); (3) `HELD_CACHE_MAX + 2` further foreign sends in a second room (the Broadcast Room), read through the same real path, fill the cache past its cap — `held.json` byte-inspection shows all records surviving, exactly 100 cached copies, the original record metadata-complete with its body copy evicted — and then the HUMAN surface (`agent-room held list`, then `agent-room held show <room_id>:<seq>`) recovers the body by point read, provenance-named, and the shown artifact BYTE-MATCHES the durable log (the SQLite file opened read-only as the oracle, the envelope rebuilt around the stored text in the test); (4) `agent-room allow Stranger` persists the fingerprint entry (note `chat_id=Stranger`), releases all records of that key, and the follow-up foreign send arrives DELIVERED — the frozen row shape with no held fields, the body present inside the literal untrusted envelope; (5) `agent-room allow Stranger --remove` removes the entry and the next foreign send is held again, while the past stays untouched: the delivered seq never re-enters held state and the durable log keeps every row's raw bytes; (6) cursor snapshots at every step prove monotonicity per room, and each CLI invocation is proven not to move the agent's cursor (byte-identical `cursors.json` across every human command).

## Boundaries & Constraints

**Always:** keep the drill zero-mock — real spawned server child, real `mcp-stdio` children over real stdio JSON-RPC, real HTTP only through the shipped clients, the real CLI dispatch with injected streams, read-only SQLite inspection for oracles; build every expected value as a literal in the test file (the held marker, the v1 envelope, the metadata line shape, the CLI line fragments) — never from a production module; state the declared-remote seam honestly in the test header, this spec, and the evidence note, including what it does NOT prove (no literal cross-machine wire — Epic 4); keep the seam strictly fail-closed — an exact match on `remote` declares, every other value (absent, `local`, a typo, garbage) keeps the earned behavior, and the programmatic option refuses anything but `undefined`/`'remote'` so `'local'` can never be declared; enumerate the zero-body proof over whole serialized tool results rather than sampling fields, with newline-free fragments so JSON escaping cannot hide a leak; keep the chain's order the shipped order — matrix evaluation, then cursor persist, then held registration — by asserting exactly what that ordering makes observable (cursor at the held seq, held state registered after, `held_count` matching); verify eviction's record-preservation rule against the real `held.json` bytes (records survive, bodies capped, the original record metadata-complete); take the recovery oracle from the durable log itself (read-only SQLite), rebuild the envelope around the stored text in the test, and compare Buffers; snapshot `cursors.json` after every step and assert per-room monotonicity plus byte-stability across each CLI invocation; assert state-file discipline (0600 files, 0700 directories); keep the runtime bounded (the drill completes in seconds; children and the server are reaped by ordered `t.after` cleanup).

**Block If:** any body byte of a held message reaches ANY agent-visible result (`message_read`, `room_held_list`, `room_held_count`) — halt; that is FR-10's plugin-enforced core failing through the real path. The cursor regresses at any step, fails to persist under (installation, realm, room), or stalls on a held seq — halt; FR-20 and the review H3 fix. The recovered preview differs by one byte from the durable log's artifact — halt; the recovery contract (spec-3-3) or the CLI's seam (spec-3-4) regressed. `allow` releases records of another key, reports success without persisting the entry, or fails to deliver the follow-up send — halt. `--remove` re-holds the past (a delivered seq re-entering held state), withdraws already-ingested text, or rewrites the durable log — halt; removal affects future delivery only. The seam could ever loosen a trust decision (a declared mode delivering something the earned mode would hold, or a typo/garbage value reading as `local`) — halt; the declaration is fail-closed or it is wrong. The drill needs a mock, a stub, a production-computed expected value, or a simulated room page to pass — halt; the story IS the real chain.

**Never:** do not change the trust matrix's cells, the held pipeline's contracts, the CLI's behavior, the nine-tool surface, or any wire API — the story adds one drill plus one fail-closed declaration seam and nothing else; do not make the adapter pass the connection mode through anything but the api-client's own declaration (no tool argument, no message field — a sender can never claim a transport, D13's discipline extended to transports); do not accept `'local'` as a declarable mode (it is earned by the token exchange alone); do not prove the chain at the composed layer (no `applyTrustMatrix` call in the test — the matrix runs inside the real child); do not compute the held marker, the envelope, or the CLI output from production modules; do not restate a numeric limit literal outside `server/constants.mjs` (the test imports `HELD_CACHE_MAX`/`READ_PAGE_MAX` by name); do not skip, `.only`, or todo anything; do not commit release artifacts or claim Epic 4's remote wire is proven.

## Design Notes

- **Why the chain needs a declared input at all.** FR-10's ratified default (D15(6)) auto-delivers every sender on a Local Mode realm — a v0.2 credential path is always the shared local token, so no real v0.2 connection can produce a hold BY CONSTRUCTION (Stories 3.2/3.3/3.4 recorded this limitation and proved holds at the composed layer). The chain's receiving installation must therefore sit on the remote lane, and the only honest way to put it there today is a declaration the plugin itself owns: `AGENT_ROOM_CONNECTION_MODE=remote`, exact-match, strictly fail-closed.
- **Why an environment declaration and not an adapter option or a test hook.** The drill spawns REAL child processes; the environment is the one channel that crosses a process boundary, with direct precedent (`AGENT_ROOM_DATA_DIR`, `PLUGIN_DATA`). The api-client owns the transport as "this installation's own connection mode, learned from its own authentication — never a claim" (spec-3-2's recorded decision); the declaration extends that ownership to the installation's host, who alone knows the session crossed the OS-user boundary. A tool argument or message field would be a sender-claimable transport — forbidden by the same discipline.
- **Why the seam cannot weaken trust.** The matrix's remote lane delivers strictly less than the local lane: own-Actor (row 1) and later allowlisted entries (row 3) deliver identically under either declaration; everything the local lane delivers beyond that, the remote lane holds. A declared remote mode can therefore only convert deliveries into holds — the fail-closed direction. A typo or garbage value is inert (earned behavior); only the exact string `'remote'` declares.
- **Why one test.** The story IS one chain; splitting it would let a link pass in isolation again — the exact failure the story exists to prevent. The single test runs in seconds (measured ~1 s), so no runtime hygiene split is needed.
- **Why the recovery oracle reads SQLite directly.** The byte-match must bind the human surface to the DURABLE truth, not to the pipeline's cached copy (which was evicted) or to a test constant (which would not catch an envelope/store drift). The test rebuilds the v1 envelope around the stored text with its own literal template and compares Buffers.
