## Findings

**F1 · The cross-machine demonstration found a defect that no test could have
found.** The shipped `web/app.js` read the boot descriptor's `broadcast_room_id`
from the TOP LEVEL of the response, but the API answers in the standard
`{ok: true, result: {…}}` envelope. Every viewer load reported "Room server
unreachable" against a healthy server — the viewer had never worked, and the
whole viewer epic's suite was green because no test ran the shipped script.
*Source: the cross-machine run's browser observation; fixed in `cc7eb6e`.*
*Disposition: **fix now** — done, with `tests/viewer-app.test.mjs` running the
shipped script against the real boot envelope (it fails without the fix).*

**F2 · The candidate-immutability law proved it can still bite.** Two packaged
changes (the viewer fix, the version stamp) voided a candidate that had already
passed an 8-hour soak. The identity proof refused the run and named the drift
instead of quietly soaking a different artifact. *Source: the soak's refusal
message.* *Disposition: **fix now** — the candidate was re-cut once, with both
changes folded in first.*

**F3 · The version stamp was an ordering trap, caught before it cost a night.**
The release notes deferred the v0.2.0 stamp to the closeout, after REL-1 — but
the stamp touches packaged bytes, so applying it then would have voided the
candidate a second time. The advisor review of the re-cut caught it while the
plan was still being made. *Source: the re-cut round-table.* *Disposition: **fix
now** — the stamp moved before the re-cut (`fcf5504`), so the shipped bytes and
the frozen bytes are the same bytes.*

**F4 · "Local Mode is the default" made the first real network path cheap to
set up — and the real one expensive to keep.** The local bootstrap (the server
boots on demand, the token file is local) is what let three vendors be wired in
minutes; the remote path (invites, challenge/answer, a CA, an enrollment) took
a real CA, a docker publish to escape the host firewall, and two machines with
their own vendor CLIs. *Source: the cross-machine run.* *Disposition: **accept**
— the difficulty is in the deployment, not the protocol, and the deployment guide
already owns that ground.*

**F5 · The trust matrix's HOLD path proved itself on a real network.** A message
from the other machine arrived withheld — metadata only, body absent, reason
`not_allowlisted` — and was released by an allowlist entry. The remote
transport is not the local-token lane, so the matrix failed closed exactly as
designed, over a real wire, between two real agents. *Source: the cross-machine
run.* *Disposition: **accept** — this is the strongest evidence in the epic that
the Epic 3/4 trust design works as written.*

**F6 · The local model on the second machine was a detour the operator's own
infrastructure was better at.** The staging host already ran a router with
dozens of model seats; the local model was installed first, was too slow to
drive an MCP turn inside a reasonable window, and was replaced. *Source: the
cross-machine run's setup.* *Disposition: **accept** — but the lesson is
recorded: when a host already has a model gateway, use it.*

**F7 · The gap that let the viewer bug survive was a TEST-SHAPE gap, not a
missing test.** The viewer epic had a test file for the viewer — and it asserted
the SERVER's contract (the boot descriptor's shape, the SSE frames, the
exposure rules) without ever running the shipped CLIENT script against it. The
client's read of a perfectly-shaped response was therefore never checked.
`tests/viewer-contract.test.mjs` now wires the real server to the real script;
`tests/viewer-app.test.mjs` runs the script against a literal fixture. Both
fail if the fix is reverted. *Source: the cross-machine run's browser
observation; the two new test files.* *Disposition: **fix now** — done.*

**F8 · Two suite failures are load-sensitive, and the diagnosis is stated
rather than assumed.** The churn memory-pass and the SM-C1 re-measurement pass
alone and fail under the parallel suite's load. *Source: the suite runs at
`d96b491`.* *Disposition: **accept, with the caveat recorded** — the candidate
record carries both the loaded and the quiet SM-C1 runs.*

**F9 · The story-build workflow's unattended proof remains unproven through a
third carry.** Every story in this epic was hand-looped; the provider
instability that made the workflow unreliable in Epics 4 and 5 persisted.
*Source: the epic's own commits and the review records.* *Disposition: **defer**
— process, not product; carried forward with the same wording for a fourth time.*

## Acceptance verdict

**accepted-with-open-items**

The epic's own criteria are not all met yet: the endurance verdict for the
shipped artifact is still running and the physical demonstration is the
operator's step. What is settled is settled decisively — the candidate is frozen,
deterministic, reproducible, and passes all five Story 6.3 gate rows; the
shipped artifact was proven against three real vendor hosts on one machine and
against two real machines over the public internet; and a real defect found
along the way is fixed with a test that runs the shipped code. Two open items
remain and both are named, dated, and owned.
